# UNESCO World Heritage Centre — Database Portal

A production-ready, full-stack portal over the UNESCO World Heritage database
(13 normalized tables covering sites, managers, funds, donations, committees and
awards), with role-based access, a full audit trail, and a dynamic, self-describing UI.

**Monorepo layout**

```
world-heritage-portal/
├── apps/
│   ├── api/     Express + PostgreSQL REST API   → deploy to Render
│   └── web/     React + Vite frontend           → deploy to Vercel
├── render.yaml  Render Blueprint for the API
└── package.json Local dev orchestration (runs both together)
```

**Stack:** React 18 + Vite 6 · Express 4 + Node (ESM) · PostgreSQL (raw SQL via `pg`)
Hosted on **Vercel** (web) + **Render** (api) + **Neon** (database). No ORM, no Docker.

---

## Features

- **Role-based auth (RBAC)** — JWT access token (in memory) + rotating httpOnly refresh cookie. Roles: `USER` (read + search) and `ADMIN` (full CRUD).
- **Generic, metadata-driven API** — one registry describes every table; the frontend renders tables, filters and forms from `GET /api/meta`.
- **Search & filter** — free-text search, per-field filters (contains / eq / gt / gte / lt / lte), sorting, pagination.
- **Version control / audit trail** — every admin write stores a before/after snapshot + diff; admins can **revert** any change (append-only).
- **Soft deletes** — deletes move records to a **Trash** view; they can be **restored**.
- **Analytics dashboard** — sites by category & region, funds by type, fund utilization, donations over time, danger-site count.
- **Full-text search** — PostgreSQL `tsvector` with ranked results and highlighted snippets.
- **Site map** — Leaflet/OpenStreetMap, colored by danger status.
- **CSV / JSON export** and **validated bulk import** (admin).
- **In-app feed + watchlist** — watch records and see their changes.
- **Dynamic schema editor (admin)** — add/rename/drop columns; changes are logged and appear live in the UI.
- **Security** — Helmet, CORS allowlist, rate limiting, bcrypt hashing, parameterized SQL, cross-site-safe cookies.

## Run locally

**Prerequisites:** Node.js 18+ and a PostgreSQL database (local, or a free Neon one).

```bash
# 1. Configure the API
cp apps/api/.env.example apps/api/.env      # set DATABASE_URL (+ DATABASE_SSL=true for Neon)

# 2. Configure the web app (optional locally — the dev server proxies /api)
cp apps/web/.env.example apps/web/.env

# 3. Install everything, create tables, and load sample data
npm run setup

# 4. Start the API (:4000) and the frontend (:5173) together
npm run dev
```

Then open http://localhost:5173.

| Role  | Email          | Password     |
|-------|----------------|--------------|
| Admin | admin@whc.org  | Admin@12345  |
| User  | user@whc.org   | User@12345   |

Root scripts: `npm run dev`, `npm run setup`, `npm run db:setup` (init + seed), `npm run db:init`, `npm run db:seed`, `npm run build:web`.

## Deploying to Neon + Render + Vercel

### 1. Database — Neon

1. Create a project at [neon.tech](https://neon.tech) and copy the connection string
   (looks like `postgresql://user:pass@ep-xxx.neon.tech/dbname?sslmode=require`).
2. From your machine, point the API at Neon and create the schema + seed data **once**:

   ```bash
   cd apps/api
   DATABASE_URL="postgresql://...neon.tech/db?sslmode=require" DATABASE_SSL=true npm run db:init
   DATABASE_URL="postgresql://...neon.tech/db?sslmode=require" DATABASE_SSL=true npm run db:seed
   ```

   `db:init` is destructive (drops & recreates tables), so run it only when setting up.

### 2. Backend — Render

1. Push this repo to GitHub.
2. In Render: **New → Blueprint**, select the repo (Render reads `render.yaml`).
   Or create a **Web Service** manually with **Root Directory** = `apps/api`,
   Build = `npm install`, Start = `npm start`.
3. Set these environment variables (the blueprint prompts for the secret ones):
   - `DATABASE_URL` — your Neon connection string
   - `DATABASE_SSL` = `true`
   - `CLIENT_ORIGIN` — your Vercel URL, e.g. `https://your-app.vercel.app`
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD` — bootstrap admin
   - `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` — auto-generated by the blueprint
4. Render exposes the service at `https://your-api.onrender.com`. Health check: `/api/health`.

### 3. Frontend — Vercel

1. In Vercel: **New Project**, import the repo, set **Root Directory** = `apps/web`
   (framework auto-detected as Vite; `vercel.json` handles SPA routing).
2. Add one environment variable:
   - `VITE_API_BASE_URL` = `https://your-api.onrender.com` (your Render URL, no trailing slash)
3. Deploy. Vercel gives you `https://your-app.vercel.app`.

### 4. Connect the two

Make sure Render's `CLIENT_ORIGIN` equals your exact Vercel URL. This is required for:
- **CORS** — the API only accepts requests from allowlisted origins.
- **Cross-site cookies** — in production the refresh-token cookie is issued as
  `SameSite=None; Secure`, so the browser sends it from Vercel to Render over HTTPS.

That's the whole reason the previous version wouldn't deploy: the frontend used a
relative `/api` proxy (dev-only) and same-site cookies. This version uses
`VITE_API_BASE_URL` and cross-site-safe cookies, so the three services work together.

## API reference

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| POST | `/api/auth/register` \| `/login` \| `/refresh` \| `/logout` | public | Auth |
| GET | `/api/auth/me` | auth | Current user |
| GET | `/api/meta` | auth | Table + field metadata |
| GET | `/api/:resource` | auth | List (`page`, `limit`, `sort`, `order`, `search`, `filters`, `view`) |
| GET | `/api/:resource/:id` | auth | One record |
| POST / PATCH / DELETE | `/api/:resource[/:id]` | admin | Audited writes (delete = soft) |
| POST | `/api/:resource/:id/restore` | admin | Restore from trash |
| GET | `/api/:resource/search?q=` | auth | Full-text search (sites) |
| GET | `/api/:resource/export?format=csv\|json` | auth | Export the filtered view |
| POST | `/api/:resource/import` | admin | Validated bulk import |
| GET / POST / DELETE | `/api/watch` · GET `/api/feed` | auth | Watchlist + feed |
| GET | `/api/history` · POST `/api/history/:id/revert` | auth / admin | Audit trail + revert |
| POST / PATCH / DELETE | `/api/schema/:resource/columns[/:column]` | admin | Schema editor |
| GET | `/api/stats` | auth | Dashboard aggregates |

Composite-key resources (e.g. `awards`) use `/api/:resource/detail?year=&country_code=&category=`.
